# POCSAG asynchronous receiver and UI

This is an optional component compiled into the application libraries and QML module, but **not connected** to the application session or IQ source. No DspEngine, SessionManager or Main wiring is provided. The host must connect a single IQ producer, choose the IQ sample rate, baud and channel offset, and implement lifecycle dispatch. `PocsagReceiver` combines the existing bounded `AsyncIqDecoder` IQ queue, `PocsagIqReceiver`, and a bounded SPSC result queue. `PocsagController` and `PocsagDialog.qml` expose a requested-enabled flag, host-reported active state, counters, and the decoded address, function, text and corrected-bit count. The controller holds the 500 most recent messages in a bounded list model, discarding the oldest entries; generation changes clear the history. Each 100 ms poll consumes at most 32 queue slots, including stale entries. Excess unread results remain queued for later polls; if the receiver result queue fills it drops incoming results and increments the loss counter. History eviction does not increment that queue-loss counter. There is no persistent storage. Text is shown as plain text and may contain control characters or padding. RAM is not securely erased. Only one result consumer is allowed, so a host must choose the controller or another consumer.

## Thread and lifecycle contract

- `configure`, `start`, `stop`, destruction, and all other lifecycle control must be serialized; the producer and result consumer must be quiescent before configure/start/stop/destruction. Pause controller polling during those transitions. `start`, configuration, and especially `stop`/destruction can allocate or block. Run them away from UI and real-time threads. The dialog emits `enabledRequested`; the host must dispatch that request and report completion with `setActive` on the UI thread. No host wiring is included here.
- Once started, exactly one producer calls `submit` and `discontinuity`. Submission copies into preallocated bounded storage and never waits. A full queue, oversized block or invalid pointer marks a gap: the next accepted block resets the decoder on the worker. The caller must report upstream dropped samples, retune and other discontinuities. The component cannot detect upstream loss itself.
- The single consumer calls `read`; results from older generations are discarded after reconfiguration/start or `stop(false)`. `stop(false)` cancels queued work and invalidates results, while `stop(true)` drains and leaves results readable until the next start/configure. A reported input gap increments the generation: unread results and queued IQ from the prior generation are discarded, and the decoder resets for subsequent input. An unreported loss cannot be detected here. A decoder callback already executing may have completed before a stop request.
- The result ring is bounded and drops new results when full; `droppedMessages` counts these, and `stats` reports input losses. Counters are cumulative for the lifetime of the object. Results expose raw 7-bit alpha data, which can include controls and padding. No numeric format inference or authentication is performed. BCH can miscorrect; there is no POCSAG message CRC.
- A worker callback or instrumentation hook that never returns prevents join. Shutdown is safe only when the producer is quiescent and the worker eventually returns. The optional hook exists for deterministic tests and should be null in production. There is no measured latency, CPU or real-time performance guarantee.

## Tests

All paths remain under `/Volumes/Projects/decodium-sdr`. Set `DSDR_TEST_SILENT_AUDIO=1`, `TMPDIR` and XDG paths under the build directory when running. The test executables print no decoded payload or capcode.

```sh
DSDR_TEST_SILENT_AUDIO=1 TMPDIR=/Volumes/Projects/decodium-sdr/build XDG_CACHE_HOME=/Volumes/Projects/decodium-sdr/build/xdg-cache XDG_CONFIG_HOME=/Volumes/Projects/decodium-sdr/build/xdg-config c++ -std=c++17 -O2 -Wall -Wextra -Werror -pthread -Isrc src/dsp/PocsagDecoder.cpp src/dsp/PocsagAudioDecoder.cpp src/dsp/PocsagIqReceiver.cpp src/core/AsyncIqDecoder.cpp src/core/PocsagReceiver.cpp tests/standalone/pocsag/test_async.cpp -o build/pocsag-async-test
DSDR_TEST_SILENT_AUDIO=1 TMPDIR=/Volumes/Projects/decodium-sdr/build XDG_CACHE_HOME=/Volumes/Projects/decodium-sdr/build/xdg-cache XDG_CONFIG_HOME=/Volumes/Projects/decodium-sdr/build/xdg-config ./build/pocsag-async-test
```

The async test compares decoded content in memory against the synchronous IQ decoder on synthetic FM IQ; verifies selected frequency and sample-rate/baud changes, stale generation rejection, invalid/oversized input, deterministic full-queue gap reset, held-worker generation invalidation, explicit mid-message discontinuity followed by recovery, bounded result overflow, and joining a temporarily held worker. It does not print the synthetic content. AddressSanitizer and UndefinedBehaviorSanitizer were also run. The standalone offscreen Qt test `tests/standalone/pocsag/test_ui.cpp` loads the real dialog with a test Theme, checks enable requests and state, and verifies synthetic decoded address, function and text in the controller and dialog, changes configuration and verifies clearing and a fresh result, tests eviction/order for 600 synthetic entries, and checks a 40-message queue drains in 32/8 batches. It is not a test of the actual application window, host wiring, physical RF, production shutdown, or reception of independent recordings. Existing IQ/bitstream limitations still apply.
