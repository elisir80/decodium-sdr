# VDL Mode 2 reference baseline

This is a reference test, not an integrated decoder or an A/B comparison.
`run_onair_baseline.sh` runs the upstream Rust protocol tests offline and
places build output in this project's build tree. Set `ONAIR_ROOT` to the
OnAir 3.9.0 source tree and `CARGO` to a working Cargo executable. For an
isolated rustup installation, set `CARGO_HOME` and `RUSTUP_HOME` too. No audio
device is opened. The reference checkout used here was commit
`15a2907f02f7486fc64b8e439a1645eb7373171f`.

OnAir combines a C++ D8PSK IQ receiver, a Rust link-layer crate and ancillary
aeronautical parsers; reproducing just the Rust protocol tests does not prove
reception, Decodium integration, or interoperability. A suitable application
integration still needs bounded asynchronous IQ handling and gap fencing,
source and result lifetimes, platform build and attribution, and a direct A/B
comparison of both receivers on identical valid and invalid IQ recordings.

`run_abi_ab.sh` builds the project-local Rust VDL2 workspace offline, links the
same ABI test once to the original OnAir static library and once to the
isolated library, and compares a deterministic digest. It checks ABI sizes,
headers with single-bit corruption, Reed-Solomon correction/rejection and FCS.
Set `CARGO`, `CARGO_HOME`, `RUSTUP_HOME` and `ONAIR_RUST_LIB` as needed. This
does not build the Rust module into the app or test an IQ decoder.

For the isolated CMake experiment, configure with
`-DDSDR_BUILD_VDL2_PROTOCOL_EXPERIMENT=ON`, build target
`tst_vdl2_protocol_abi` and run that CTest. This requires an installed Cargo;
Cargo is invoked offline with the checked-in lockfile. Cross compilation
requires `DSDR_VDL2_RUST_TARGET` and the corresponding installed Rust target;
macOS universal builds are not supported by this experiment. The option is off
by default; when enabled it also exposes the experimental receiver in the app.
So far only
native macOS Apple Silicon has been compiled and tested.

`run_iq_queue_ab.py` additionally requires an OnAir Ninja build in which the
`test_vdl2_rx` target has completed; set `ONAIR_BUILD` if it is elsewhere.
It links a standalone experiment using that build's link dependencies. The
same synthetic IQ samples go to two instances of the **same OnAir receiver**:
one directly, one via Decodium's bounded `AsyncIqDecoder`. It verifies one
generated frame, silence, matching addresses and frequency, and no queue drops
under deterministic pacing. An oversized rejected block in the middle of a
frame also tests the queue's automatic gap marker: the interrupted frame is
rejected, and a subsequent complete frame is decoded after a fresh gap. The
test checks the rejected-block and sample counters. This verifies the queue
path for these samples; it is not a comparison of independent implementations,
an application integration test, a sustained-saturation test, or evidence of
RF reception.

The synthetic comparison also checks carrier offsets of +3200 Hz and
-3200 Hz with deterministic complex noise. These are controlled generated
signals and do not establish performance on real RF recordings.

`run_frame_reference_ab.py` uses the same OnAir Ninja build to compare the
local frame adapter with OnAir's C++ frame builder and parser. It covers both
directions, supervisory, X.25 and XID frames, plus the same four frames after
FCS corruption. Both paths use the same underlying Rust protocol library, so
this validates the adapter's field mapping and FCS gate, not an independent
implementation or over-the-air interoperability. It does not open audio.
It also generates an HDLC/FEC burst with OnAir and checks recovery of all
four frames by `Vdl2Burst`, correction of one header bit, and rejection of
truncated or non-binary input. This is a bit-layer test, not an IQ receiver.
It additionally compares `Vdl2Symbols` against the phases generated by OnAir,
with a fixed common phase rotation, and checks the resulting frames. The
symbols are supplied at their exact centres: acquisition, carrier recovery,
timing recovery and realistic RF reception remain untested and unimplemented.
The reference comparison also locates the training sequence in short windows
of OnAir-generated IQ at 105 kHz, estimates carrier offsets of +/-1200 Hz,
and rejects silence. The window is chosen around a known burst and this does
not validate unattended streaming acquisition or false-alarm performance.
The experimental finite-window receiver now links acquisition, frequency
correction, fixed-clock symbol sampling, burst recovery and FCS validation;
it recovers the four reference frames at both offsets. It does not include
channel filtering, continuous reception or adaptive symbol timing.
An additional synthetic burst contains three valid AVLC frames and one with
bad FCS: both OnAir and the experimental receiver retain the valid three.
The A/B also feeds the complete same 105 kHz synthetic IQ window, with
deterministic low noise and carrier offsets -1200, 0 and +1200 Hz, to OnAir's
receiver and the experimental receiver. Frame counts and selected parsed
fields agree. Both use related protocol code and this is not an RF test.
An experimental overlapping-window worker consumes fragmented IQ blocks;
one synthetic burst matches OnAir, is emitted only once across overlap, is
rejected after a mid-burst reset, and is recovered after a fresh full burst.
It also recovers two separate synthetic bursts in one window, matching OnAir.
The worker continues searching after an invalid candidate: in a synthetic A/B
it rejects a stronger damaged burst and recovers a subsequent weaker one, as
OnAir does. It assumes filtered IQ and a fixed symbol clock and is not wired
to the app. It limits candidate searches and excludes a guard region around
each candidate; long/overlapping bursts and traffic under load remain untested.
`Vdl2AsyncStream` runs that experimental receiver behind the existing bounded
IQ queue. Its standalone test checks a valid generated burst, then rejects a
burst interrupted by an oversized dropped IQ block. The callback runs on the
worker and is not an app/UI integration; shutdown requires a quiescent producer.
With the worker deliberately held, a queued pre-gap synthetic burst is
discarded and a post-gap burst is delivered. A callback already in progress
when a gap occurs cannot be retracted; a future UI integration must also
validate the generation when consuming queued results.
`Vdl2ResultQueue` now retains that generation with each bounded raw frame;
its test discards queued older frames, preserves current frames and counts
overflow. It is not connected to the UI yet; the consumer must obtain and
recheck the current pipeline generation when applying a result.
`Vdl2Session` owns the pipeline and queue together. Its synthetic end-to-end
test leaves one run's frames queued, restarts the pipeline and verifies that
only the next run's frames can be read. It remains a non-UI experimental API.
The optional `tst_vdl2_controller_iq` executable additionally consumes the
synthetic IQ emitted by `frame_reference_ab --emit-iq`; it checks four frames
reach the Qt model and a QML dialog, and a restart clears them. It runs with
the offscreen platform and does not prove integration into the application or
hardware reception. The fixture belongs in the build tree.

The application IQ end-to-end tests unpack the supplied synthetic fixture to
the build tree, checking its SHA-256 hash; Python 3 is required when configuring
these tests. An alternative fixture can be selected with
`-DDSDR_VDL2_IQ_TEST_FIXTURE=/absolute/path/to/synthetic.cf32`. If an explicitly
selected file is absent CMake warns and does not register the IQ tests.
The same executable now injects the IQ through DspEngine: with the raw tap
absent the model stays empty, and with the tap attached four frames reach the
QML dialog. Attach/detach occur on the quiescent test thread; application
ownership, shutdown fencing and menu wiring remain to be implemented.
The shutdown test also runs DspEngine on a separate QThread, sends one IQ
block through an attached VDL2 ingress, fences and detaches on that thread,
and checks that DecoderShutdown retains the resources until both user and
backend acknowledgements. This is a controlled lifecycle test, not the full
application shutdown or a physical-radio test.
An additional A/B sends the same synthetic 1.05 MHz IQ with a 200 kHz channel
offset and +1200 Hz carrier error to OnAir and to the experimental mixer, FIR,
decimator and async receiver; both recover the four frames. This is a single
clean simulated channel and a simultaneous equal-level synthetic signal on an
adjacent channel 25 kHz away. Both match OnAir; this does not establish RF
performance or rejection over a range of interferer levels and frequencies.
